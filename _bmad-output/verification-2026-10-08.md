# BMAD 재검토·구현·검증 결과

검증일: 2026-10-08 · 대상: 우주 끝의 등대 웹앱.

## 판단과 최종 구현

Complete Edition **96쪽**, Logbook Journal **40쪽**을 처음부터 끝까지 독립적으로 검토했다. 기존 앱을 읽지 않은 원문 검토와 별도 앱 감사의 결과를 비교했다. BMAD CIS **Design Thinking**의 여정 지도·POV/HMW·SCAMPER·대안 비교, **Problem Solving**의 Five Whys·Fishbone·Force Field·PDCA를 사용했다. 원문 자체에서 시작 → 임무 선택·판정·자유 해석·기록 반복 → 자율 마무리가 핵심임을 확인했다. 사용자 승인 체크포인트는 사용자의 명시적인 자율 진행 요청에 따라 기다리지 않았다.

기능별 메뉴를 오가던 구조를 **오늘 밤의 작업 공간**으로 재구성했다. 기본 메뉴는 오늘 밤·일지·규칙 찾기이며, 선택 도구는 데스크톱 우측과 모바일 하단 도구 메뉴로 연다. 플레이북·계절을 시작의 필수 설정으로 요구하지 않는다. 현재 임무 하나의 결과·해석·작성·관련 규칙을 같은 맥락에 두고 다음 임무로 바로 돌아간다. 예시와 서사 단서는 펼쳐 볼 수 있다.

교정한 규칙과 저장 동작:

- 점등은 같은 시도의 앞면+적색 카드만 성공하며 태엽 감기는 별도 절차다.
- 정비의 네 문양 결과, 관측의 네 거리, 사건의 13가지 숫자와 색에 따른 영향은 원문을 대조했다. 임의의 판정 보정·위험을 서사 단서에 덧붙이지 않는다.
- 사건4의 재점등,9의 이른 마무리,K의 밤 다시 시작을 진행에 연결했다. K를 일반 종료로 우회하지 못하며 기존 글을 삭제하지 않는다.
- 글 길이·임무 수·마지막 소감의 필수 분량을 강제하지 않는다. 종료 시 분위기에 맞는 1–4회 Fisher–Yates 셔플을 실제 실행한다.
- 해변에서 필요한 카드 묶음을 시작에 엎어 두고 한 장씩 카드 → 동전 → 기록/보관으로 진행한다. 수색의 묶음과 선택한 입력 방식은 새로고침·다른 임무·종료 셔플 후에도 유지된다. 보관하지 않은 발견도 일지에 남고 물건 사용이 자동 폐기로 이어지지 않는다.
- 빛은 한 밤에 한 질문만 보내며 해당 동전 결과의 전체 단어 묶음과 해석을 보관한다.
- 계절은 선택 확장이다. 표식 충족 뒤 다음 날 시작하며 이야기 속 경과를 직접 기록한다. 따뜻함은3밤, 타격은1d6÷2의 반일을 보존한다. 종료 시 표식을 비운다.
- 진행 중 글·덱·도구 상태를 자동 저장하고 전체 백업에 포함한다. 구형 일지만 가져올 때 다른 상태를 지우지 않는다. malformed 복원은 적용 전에 거부하고 잘못된 로컬 데이터의 원본을 남긴다.

디지털 덱 소진 시 재셔플과 수색 묶음이 부족할 때 전체 덱 재셔플은 앱의 편의 처리이며 알림으로 설명한다. 이를 원문의 추가 규칙으로 제시하지 않는다.

## 실행한 검사

iCloud 경로의 기존 의존 파일 일부가 미다운로드 상태여서 동일한 소스·설정·package-lock을 `/tmp/lighthouse-runtime`에 복사하고 `npm ci`로 설치한 환경에서 검사했다. 실제 수정 파일은 원래 프로젝트에 있다. 최종 production preview는 `http://127.0.0.1:5299`에서 실행했다.

| 검사 | 최종 결과 | 확인 범위 |
|---|---|---|
| `npm test` | **24/24 통과** | 52장 유일성, 소진, 동전·주사위, 점등, 임무·사건, 계절 공식, 실제 셔플 횟수, 전환·백업·손상 데이터 |
| `npm run test:browser` | **10/10 시나리오 통과** | 시작→점등→태엽→기록→마무리,4/9/K,디지털 덱,해변/예약묶음,빛,계절3밤·반일,백업/구형 가져오기,규칙/키보드/테마,손상 저장 복구 |
| `npm run lint` | 통과 | ESLint 및 React Hooks 검사 |
| `npm run build` | 통과 | production assets 생성; 초기 JS 약302kB(gzip96kB), 클라우드 코드는 설정을 열 때 별도 로드 |
| 별도 UI 감사 | 네 폭 모두 필수 오류 없음 | 320·390·768·1440px,모바일4메뉴,패널 Tab/Escape,결과 읽기,종이/밤 테마 |

브라우저 시나리오의 pageerror는 **0건**이었다. 실제 사용자의 저장소를 건드리지 않는 별도 컨텍스트와 테스트 데이터를 사용했다.

## 요청한 여섯 차원

| 차원 | 검증 결과와 근거 |
|---|---|
| 룰북 충실성 | 두 원문 전체 독립 검토와 구현 후 별도 규칙 검토. 표·순서·특수 사건·선택 확장을 자동 검사 및 실제 UI 동작으로 대조했다. 마지막 재검토의 실제 셔플·수색 예약·3밤 단위 차이도 수정했다. |
| 핵심 플레이 루프 | 새 진입에서 곧바로 오늘 밤을 시작하고, 하나의 작업 공간에서 임무 선택→판정→기록→다음 선택을 반복한다. 별도 프로필 설정이나 계절 설정을 선행 조건으로 요구하지 않는다. |
| 규칙 접근 속도 | 현재 결과의 의미를 읽기 위한 화면 이동0. 관련 상세 규칙은 결과의 링크1클릭. 선택 도구는 데스크톱1클릭,모바일2클릭. 규칙 검색이 남아 있어도 현재 임무 링크는 해당 내용을 바로 연다. 사람의 읽기 속도 개선율을 측정한 결과는 아니다. |
| 조작 수·인지 부하 | 디지털 일반 임무1회는 선택1클릭+기록 완료1클릭(글 입력 제외). 상위 메뉴 재탐색0,대기 임무1개. 모바일의 중복 도구 목록과 정비 질문 중복을 제거하고 결과부터 읽도록 포커스를 조정했다. |
| 모바일·데스크톱 | 320·390·768·1440px에서 가로 넘침0. 모바일 하단4메뉴와 데스크톱 우측 도구가 열리며 dialog 내부 Tab 이동과 Escape 후 원래 버튼 복귀를 확인했다. |
| 시각적 일관성 | 공통 색·타입·버튼·입력·상태 표현을 사용한다. 두 테마에서 결과·글쓰기·주 행동이 읽히고 선택 도구보다 높게 배치된다. 별도 에이전트가 화면과 조작을 독립 확인했다. |

## 검증의 한계

실제 참가자 인터뷰·읽기 시간·몰입도 실험은 수행하지 않았다. 모바일 검사는 Chromium viewport 기반이며 실물 기기의 가상 키보드·Safari는 별도 검증하지 않았다. Google 로그인과 실제 Firestore 백업/복원 왕복도 이번 로컬 검사 범위에 포함하지 않았다. 로컬 플레이와 파일 백업의 완료 여부와 이 제한을 구분한다.
