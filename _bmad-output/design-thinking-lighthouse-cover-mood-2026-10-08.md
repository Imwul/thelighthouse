## 🎯 Design Challenge

표지의 이미지 관계를 읽고 제품으로 번역한다. 깊은 잉크빛 우주, 은백색 등대와 별, 회청·라벤더빛 광선, 어긋난 이중 프레임, 인쇄 결, 큰 이탤릭 세리프가 표지의 특징이다. 목적은 이 관계를 시각 언어로 반영하는 것이며 표지를 그대로 붙이는 것이 아니다.

디자인은 판정·기록·다음 임무를 돕는 기존 작업 흐름을 유지해야 한다. UI의 감성적인 제목·안내·placeholder는 기능 중심으로 바꾸고, 분위기는 색·빛·별·선·질감으로 표현한다. 룰북의 플레이 프롬프트와 감정에 따른 날씨 선택은 실제 규칙 정보로 유지한다. 3440px 화면의 여유는 우주 외곽과 빛의 공간감에 쓰고 글줄을 무한히 늘리지 않는다. 좁은 화면에서는 장면이 핵심 조작과 글쓰기 공간을 밀어내지 않게 압축한다.

선정 방법: **Journey Mapping**, **Empathy Mapping**, **Analogous Inspiration**. 입력은 사용자의 실제 디자인 피드백, 표지의 시각 관찰, 룰북의 플레이 맥락, 루트가 전달한 3440px 요구다. User Interviews/Shadowing은 수행하지 않았다.

### Key Observations

**표지 직접 관찰**:

- 바탕은 보라 네온이 아닌 깊은 청색·남색 계열이며 인쇄 결로 밀도가 변한다.
- 등대는 은백색에 가까운 밝은 면과 청색 선으로 표현된다. 랜턴의 빛은 황금색보다 차갑고 흰 빛이다.
- 광선은 양옆으로 펼쳐지는 넓고 평평한 회청·라벤더색 삼각 형태다. 번쩍이는 효과보다 공간과 고요를 만든다.
- 별은 크기·위치가 달라 규칙적인 점 격자가 아니다. 큰 별은 드물다.
- 외곽의 아주 얇은 흰 이중 프레임은 조금 어긋나며 꼭짓점에 계단형 변화가 있다.
- “Lighthouse”, “Universe”는 큰 이탤릭 세리프이고 주변 작은 대문자와 크기 대비가 크다.
- 전체 관계는 오래된 천체 기록물/밤의 항해이며 매끈한 SF대시보드보다 책의 물성이 강하다.

**작업 여정에 대한 번역**:

| 순간 | 시각적 역할 | 기능 보호 |
|---|---|---|
| 오늘 밤에 들어옴 | 작은 등대·빛·별로 세계를 인식 | 첫 행동이 장면 아래 멀리 밀리지 않음 |
| 상태를 확인함 | 은백색 강조로 현재 밤·빛을 확인 | 장식과 실제 상태를 구별 |
| 결과를 읽음 | 밝은 종이 면에서 잉크색 결과 | 본문에 질감·광선 겹침 없음 |
| 기록을 씀 | 안정된 읽기폭과 명료한 커서/포커스 | 과도한 발광·배경 움직임 없음 |
|3440px로 펼쳐짐 | 외곽 우주와 빛이 자연스럽게 이어짐 | 글줄·입력창 폭은 제한 |
| 모바일로 좁아짐 | 등대 장면·프레임을 축소 | 임무·기록·내비게이션 접근 유지 |

### Empathy Map Summary

직접 발언으로 확인된 내용은 표지 색감과 신비로운 분위기 보강 요청이다. 아래 생각/행동/감정은 가설이며 인터뷰 인용이 아니다.

- **Say**: 룰북 표지와 연결되는 신비로운 분위기를 실제 디자인에 반영하라는 피드백.
- **Think**: 게임의 세계를 떠올릴 수 있으면서도 판정과 쓰기의 위치를 즉시 찾고 싶을 수 있다.
- **Do**: 밤을 열고 결과를 읽고 글을 쓰며 임무를 반복한다. 넓거나 좁은 화면에서 같은 기능을 사용한다.
- **Feel**: 고요·미지·경이의 감각을 기대할 수 있다. 반짝임과 시각적 소음이 커지면 집중을 방해할 수 있다.
- **Pain**: 일반적인 도구 화면의 무미건조함, 넓은 화면의 의도 없는 여백, 지나치게 긴 글줄, 장식이 핵심을 가리는 문제.
- **Gain**: 우주 안에서 로그북을 펼쳐 쓰는 경험, 차분한 빛의 대비, 화면 크기가 달라도 의도적인 구성.

## 🎨 DEFINE: Frame the Problem

### Point of View Statement

**밤의 등대지기 역할로 판정하고 기록하는 사용자는 룰북 표지의 신비로운 세계를 느끼면서 읽기·쓰기·다음 행동을 편안하게 이어갈 필요가 있다. 분위기를 만드는 외곽 공간과 집중을 위한 작업 면이 함께 설계되어야 하기 때문이다.**

### How Might We Questions

1. 표지의 잉크색·은백색·회청빛 관계를 상호작용 화면에서도 인식하게 할 수 있을까?
2. 등대의 빛을 장식과 실제 점등 상태 양쪽에 자연스럽게 연결할 수 있을까?
3. 오래된 인쇄물의 질감을 느끼게 하면서 규칙과 기록은 또렷하게 유지할 수 있을까?
4.3440px의 넓은 여백을 아름다운 우주 외곽으로 구성하면서 읽기폭을 제한할 수 있을까?
5. 모바일에서 같은 정체성을 유지하면서 장면의 수직 공간을 줄일 수 있을까?
6. 화려함을 늘리기보다 빛·별·선의 수를 줄여 신비로움을 만들 수 있을까?
7. 표지의 문학적 타이포를 가져오되 한국어 UI와 조작은 쉽게 읽게 할 수 있을까?

### Key Insights

- 신비로움은 색만 바꾸는 것보다 **깊은 배경·밝은 대상·빈 공간·드문 별·빛의 방향**의 관계에서 나온다.
- 기록 면은 종이처럼 밝게 둘 수 있다. 모든 면을 어둡게 만드는 것이 표지의 대비를 옮기는 유일한 방법은 아니다.
-3440px 대응은 모든 내용을 넓히는 문제가 아니라 **풍경 폭과 작업 폭을 분리**하는 문제다.
- 디지털 제품의 글·입력·판정은 인쇄물보다 또렷해야 한다. 질감과 프레임을 외곽에 제한한다.
- 큰 제목은 시작 맥락에, 작은 명료한 글은 반복 작업에 사용한다.

## 💡 IDEATE: Generate Solutions

### Selected Methods

**SCAMPER Design**으로 기존 시각 요소를 교체·결합·축소하고, **Analogous Inspiration**으로 표지의 인쇄물/항해 이미지를 제품으로 번역한다. **Provotype Sketching**으로 극단적으로 어둡거나 장식적인 대안을 비교하며, Journey Mapping으로 각 장식이 실제 단계에 필요한지 확인한다.

### Generated Ideas

1. **Substitute**: 외곽의 일반 중립 배경을 깊은 잉크 청색 우주로 바꿈.
2. **Combine**: 대표 영역의 등대·별·광선이 페이지 배경까지 이어지도록 구성.
3. **Adapt**: 랜턴의 은백색을 주요 행동과 현재 상태 강조에 적용.
4. **Modify**: 글쓰기 면을 차가운 밝은 종이색으로 조정해 외곽과 대비.
5. **Eliminate**: 네온 그라데이션·다색 광택·큰 그림자 등 표지와 무관한 강조를 줄임.
6. **Reverse**: 화면 내부보다 외곽에 장식을 두어 중심 작업이 더 조용하게 보이도록 함.
7. **Adapt**: 표지의 회청색 삼각 광선을 SVG/CSS 배경으로 재구성.
8. **Combine**: 실제 불빛 상태가 광선의 밝기와 상태줄 강조를 바꾸게 함.
9. **Modify**: 큰 이탤릭 세리프 제목과 단정한 작은 UI글자의 대비 강화.
10. **Adapt**: 한국어 제목은 차분한 명조, 버튼·본문은 고딕으로 역할 구분.
11. **Eliminate**: 별을 소수만 남기고 크기·분포를 불규칙하게 함.
12. **Adapt**: 인쇄 결은 투명도가 낮은 코드 기반 선/그레인으로 외곽에만 제공.
13. **Combine**: 얇고 어긋난 이중 프레임을 대표 영역 또는 페이지 외곽에 사용.
14. **Eliminate**: 모든 임무 카드에 이중 프레임을 반복하는 장식을 없앰.
15. **Modify**:3440px에서 최대 작업 폭을 제한하고 바깥을 의도된 우주 풍경으로 둠.
16. **Modify**: 데스크톱에서는 참고 도구와 기록 면을 나란히, 글줄은 안정된 폭으로 유지.
17. **Eliminate**: 모바일에서 과도한 장면 높이·장식 여백을 축소.
18. **Adapt**: 포커스는 밝은 단선, 활성 탭은 은백색 밑줄로 일관되게 표시.
19. **Purposes**: 별 모티프를 드문 구분점/장식에 활용하되 일반 버튼 아이콘으로 남발하지 않음.
20. **Reverse**: 움직이는 별/회전 효과 대신 정적인 공간감과 부드러운 밝기 변화로 분위기를 만듦.

## 🛠️ PROTOTYPE: Make Ideas Tangible

### Prototype Approach

**Storyboarding**으로 진입→점등→임무→기록→마무리의 시각 역할을 확인하고, 실제 코드에서 SVG/CSS로 장면과 디자인 토큰을 구현한다. 별도 래스터 생성은 필요하지 않다. 등대의 단순 기하학, 빔, 별, 프레임은 크기·색·상태에 따라 조절되는 코드 기반 벡터에 적합하다.

원본 표지는 관찰 근거로 유지하며 그대로 복사·자르기·배경화하지 않는다. 새 등대 실루엣과 빛의 배치를 제품의 비율에 맞게 만든다.

### Prototype Description

**구체적 시각 원칙**:

1. **팔레트**: 제안색은 외곽 `#102b53`, 보조우주면 `#18385f`, 은백강조 `#e6edf1`, 회청광선 `#a3aec4`, 밝은 기록면 `#f0f2ee`. 표지에서 기계 추출한 정확한 색값이 아니라 직접 관찰에 따른 제품 토큰 제안이다.
2. **빛**: 은백색 랜턴과 넓은 회청빛이 대표 영역에서 양옆으로 퍼짐. 소등일 때보다 점등/태엽 이후 더 선명하되 입력과 결과 위에 겹치지 않음.
3. **프레임**: 대표 영역/외곽에 가는 이중 선. 카드마다 반복하지 않고 기능적 경계는 단순 선·면 차이로 표시.
4. **질감**: 외곽 우주만 약한 인쇄 결. 입력·규칙·기록 영역에는 읽기 방해 질감 없음.
5. **타이포**: 대표 영어 제목 이탤릭 세리프, 한국어 제목 명조, 본문/조작은 고딕. 문자마다 광택/그림자를 적용하지 않음.
6. **3440px**: 우주 배경과 별/광선은 화면 전체를 사용하되 메인 작업영역은 대략 1440–1680px 상한. 글쓰기/장문 영역은 대략 720–900px 수준, 참고는 280–360px 수준으로 제한하는 방향을 검증. 실제 토큰은 코드 레이아웃과 화면 확인으로 조정한다.
7. **모바일**: 장면은 수직 높이를 줄여 핵심 임무/기록 접근을 유지. 별과 프레임을 줄이고 동일 팔레트·빛 대비로 정체성을 보존.

외곽을 장식으로 채우는 대신 좌우의 긴 고요한 공간에 소수 별·미약한 인쇄 결·한 방향의 넓은 빛을 둔다. 3440px에서도 본문은 읽기 좋은 중심에 머물고, 화면 전체에 동일 문장을 늘어뜨리지 않는다.

### Key Features to Test

- 첫 화면에서 표지의 남색·은빛·광선·별·세리프 관계가 실제로 나타나는가.
- 판정 결과·본문·작성 중 글의 대비와 읽기폭이 유지되는가.
- 점등 상태·활성 탭·포커스·주요 행동이 일관되고 장식과 구별되는가.
-3440px에서 우주 외곽이 의도적으로 구성되며 중심 콘텐츠가 지나치게 넓어지지 않는가.
- 데스크톱/모바일에서 대표 영역 높이가 핵심 작업을 가리지 않는가.
- 프레임·질감·빛이 클릭 대상이나 입력창을 덮지 않는가.
- 기존 핵심 기능 흐름과 저장 상태가 시각 변경 후 유지되는가.

## ✅ TEST: Validate with Users

### Testing Plan

이번 단계 검증은 **구현 후 브라우저 화면 확인·과제 수행·빌드/린트**다. 모바일, 일반 데스크톱, 3440px폭에서 진입·점등·임무·기록·보조 도구·마무리를 확인한다. 레이아웃의 가로 넘침/잘림, 글줄, 장식의 겹침, 대표 영역과 핵심 작업의 거리, 포커스, 밝고 어두운 면의 일관성을 검사한다.

스크린샷의 인상만으로 기능 검증을 대체하지 않는다. 분위기 만족도는 실제 사용자 판단이 필요하며 이번 대리 화면 검증으로 실측 체감 효과를 주장하지 않는다. 추후 참가자에게 표지 / 웹앱의 연관감, 밤의 집중감, 읽기 편의를 묻고 실제 짧은 플레이를 관찰할 수 있다.

**신규 인터뷰/실험 피드백**: 수집하지 않음. 분위기나 몰입이 개선되었다는 실측 수치를 만들지 않는다.

### Key Learnings
