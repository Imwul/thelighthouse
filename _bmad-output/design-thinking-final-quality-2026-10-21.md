# Design Thinking Session: 우주 끝의 등대 최종 품질 감사

**Date:** 2026-10-21 (Asia/Seoul)
**Facilitator:** Codex
**Design Challenge:** 기록과 규칙 참조의 흐름을 보존하며 기능적 완성도와 편집적 품질을 높인다.

## Design Challenge

사용자의 전면 감사·직접 수정·실제 브라우저 검증·Git push 요청을 입력 브리프로 사용했다. README, 현재 소스, 기존 검증 기록과 실제 Chromium 화면을 근거로 한다. 기존 문서는 덮어쓰지 않는다.

설치 스킬을 새로 스캔했다. core-tools, cis, tea 모듈을 확인했다. `bmad-cis-design-thinking`의 SKILL.md·customize.toml·design-methods.csv·template.md를 읽고 resolve_customization.py와 resolve_config.py로 활성 설정을 확인했다. 추가 활성 단계·지속 사실·완료 지시는 없다. 사용자의 명시적인 자율 실행 요청에 따라 대화형 체크포인트를 생략했다. TEA는 설치되어 있지만 이 프로젝트에 modules.tea 설정이 없어 이번에 실행했다고 주장하지 않는다.

## EMPATHIZE: Understanding Users

**방법 선택:** Journey Mapping, Empathy Mapping, Assumption Testing. 인터뷰·섀도잉·다이어리 연구도 검토했지만 실제 참가자를 확보하지 않은 이번 실행에서 관찰 자료로 주장하지 않는다.

**사용자 가설:** 혼자 밤의 장면을 상상하며 기록하는 한국어 플레이어. 모바일로 짧게 쓰거나 데스크톱에서 긴 글을 쓴다. 기존 백업을 가져오고, 쓰던 글을 두고 규칙과 선택 도구를 확인한다.

**여정:** 날짜/기분 → 점등 실패/성공 → 태엽 → 임무 판정/해석 → 기록 → 선택 도구/규칙 → 소등/셔플 → 일지 → 검색/내려받기 → 복원/다음 밤.

**관찰:** 기본 시나리오 10개는 통과했지만 검색 무결과·본문 검색·구형 복수 기록의 ID·저장 실패 중 정규화는 검증 밖에 있었다. 도구에서 규칙을 열면 돌아가는 직접 동선이 없다. 일지와 규칙이 플레이 기록 면과 같은 카드/그림자를 반복한다.

**공감 지도(추정):** “내 글이 남아 있나?”라고 생각하며 새로고침하고, 규칙을 찾다가 방금 쓰던 도구로 돌아가고 싶어 한다. 기록을 잃을 때의 영향은 장식의 취향 차이보다 크다.

## DEFINE: Frame the Problem

**POV:** 기록을 오래 쌓는 솔로 플레이어에게는 읽은 자료를 안정적으로 복원하고 작업 맥락을 잃지 않는 도구가 필요하다. 몰입은 판정의 속도뿐 아니라 글이 안전하다는 신뢰와 읽기의 리듬에 달려 있기 때문이다.

**How Might We:**
- 어떻게 오래된 백업의 여러 기록을 개별 기록으로 다룰 수 있을까?
- 어떻게 저장 실패 때도 이미 읽은 글을 계속 보여주고 파일로 보관하게 할까?
- 어떻게 사용자가 기억하는 규칙의 본문 단어로 찾게 할까?
- 어떻게 규칙을 확인한 뒤 쓰던 도구로 돌아가게 할까?
- 어떻게 플레이·일지·참고서의 역할에 맞게 서로 다른 읽기 리듬을 줄까?

## IDEATE: Generate Solutions

**선택 방법:** SCAMPER Design(반복 장식/단계 제거), Analogous Inspiration(로그북과 참고서), Brainstorming. Crazy 8s·Provotype도 검토했으나 화면 전면 변경은 이 작업의 제약에 맞지 않는다.

**발산한 18개 아이디어:**
1. 데이터 경계에서 누락/중복 ID 보완.
2. UI에서 배열 인덱스를 ID로 사용.
3. ID 없는 구형 파일 거부.
4. 정규화와 보조 백업 저장의 실패 경계 분리.
5. 저장 실패 시 읽기 전용으로 전환.
6. 모든 기록을 IndexedDB로 이전.
7. 본문과 같은 콘텐츠 트리에서 규칙 검색 색인 생성.
8. 별도의 수동 키워드 사전 확대.
9. 서버 검색 추가.
10. 검색 공백/대소문자/유니코드 정규화.
11. 검색 0건의 명시적 안내와 초기화.
12. 검색 결과에 새 장식 배지 추가.
13. 규칙에서 원래 도구로 돌아가는 버튼.
14. 모든 도구를 새 창으로 열기.
15. 일지의 반복 카드 간격과 그림자를 장부형 행으로 교체.
16. 규칙 주제의 개별 박스를 밑줄 탭으로 정리.
17. 현재 등대/청색/종이/세리프 체계를 보존.
18. 모든 화면을 새로운 대시보드 디자인으로 통일.

**선택한 3개 콘셉트:** 안전한 기록 경계(1,4), 찾고 돌아오는 참고 도구(7,10,11,13), 역할에 맞는 편집(15,16,17). 2는 삭제 대상이 이동할 수 있고 3은 기존 자료를 거부한다. 6/9는 과도한 아키텍처 변경, 12/18은 정체성을 희석한다.

## PROTOTYPE: Make Ideas Tangible

**방법:** Role Playing으로 여정을 직접 실행하고, 기존 코드 위에서 작은 기능 변경을 만들어 Assumption Testing한다. 사용자의 요청에 따라 결과는 실제 구현이며, 가짜 백엔드나 플레이스홀더는 만들지 않는다.

**범위:** ID 정규화, 메모리 데이터 보존, 검색·복귀 버튼, 선택 상태 접근성, 긴 제목 줄바꿈, 일지 행과 규칙 탭의 시각적 조정. 플레이 판정 규칙과 주요 콘텐츠는 유지한다.

**검증할 기능:** 복수 구형 일지의 독립 열기/삭제, 소지품과 대화의 개별 동작, 저장 용량 오류에서 원문 유지/백업, 본문 검색/무결과/초기화, 도구→규칙→도구, 전체 플레이와 반응형 회귀.

## TEST: Validate with Users

**실행 검증:** 자동 단위 테스트와 실제 Chromium의 격리된 가상 데이터를 이용한 UI 과제. 구체 결과는 `verification-2026-10-21.md`에 기록한다. 데스크톱·모바일 화면을 캡처하고 사람이 읽는 방식으로 확인한다.

**실제 참가자 피드백:** 수집하지 않았다. 이 문서의 공감 지도는 가설이며 실제 인터뷰가 아니다.

**후속 사용자 테스트 계획:** 5–7명(신규 2명, 기존 솔로 RPG 사용자 2명, 모바일/키보드 사용자 1–3명)이 한 밤 기록, 본문 규칙 검색, 선택 도구 복귀, 구형 백업 복원을 수행한다. 첫 클릭, 막힌 지점, 도움 요청, 글을 잃었다고 느낀 순간을 기록한다. 성공률·과제 완료·잘못 삭제한 기록 0건을 살핀다.

기능 및 화면 검증을 통과한 변경만 커밋한다. 실제 참가자 피드백과 클라우드 인증/왕복은 별도 미검증 항목으로 남긴다. 검증한 로컬 결과와 원격 push, 실제 배포 상태를 각각 구분한다.
