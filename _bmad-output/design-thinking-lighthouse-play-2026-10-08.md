# Design Thinking Session: thelighthouse-apo

**Date:** 2026-10-08 (Asia/Seoul)
**Facilitator:** Codex, BMAD Creative Intelligence Suite
**Design Challenge:** 룰북에 충실하면서 혼자 하는 밤의 저널링 흐름을 가장 빠르고 자연스럽게 지원하는 플레이 도구로 웹앱을 재설계한다.

진행 원칙: 사용자가 분석부터 실제 코드 수정·검증까지 자율 실행을 명시했으므로 BMAD의 중간 승인·인터뷰 질문 체크포인트를 기다리지 않는다. 두 PDF를 독립적으로 전부 읽고, 현재 앱은 별도의 감사로 조사한다. 실제 참가자 인터뷰·관찰·A/B 실험을 했다는 주장은 하지 않는다. 아래 사용자 이해는 룰북의 플레이 경험과 대리 과제 수행을 근거로 한 가설이며, 실사용 검증과 구분한다.

## 🎯 Design Challenge

**도전 정의**: 밤마다 등대지기는 감정으로 날씨를 선택하고, 불을 켜고 태엽을 감은 뒤, 원하는 임무를 골라 판정하고 자신의 이야기를 기록한다. 임무와 기록을 여러 번 오가다가 만족하면 소등하고 마지막 소감을 남긴다. 제품은 이 순서를 기억할 부담을 덜고 해석과 쓰기를 돕되, 플레이어가 이야기의 선택권을 유지하게 해야 한다.

**성공 기준**: 필요한 규칙이 판정·기록 맥락에 나타나고, 다음 임무를 고르는 동안 기록이 사라지지 않으며, 모바일/데스크톱 모두 핵심 루프를 같은 개념으로 사용할 수 있다. 단순히 규칙표를 더 많이 노출하거나 그림을 더 크게 만드는 것을 개선으로 간주하지 않는다.

### Empathy Map Summary

아래 생각/감정은 참가자의 직접 발언이 아니라 룰북에 근거한 가설이다.

- **Say**: “이 결과를 어떻게 해석하지?”, “다음에 어떤 일을 할까?”, “이 밤에 남겨둘 것은 무엇일까?”
- **Think**: 판정 규칙은 기억하기 어렵지만 자신의 이야기와 연결하면 의미가 생긴다.
- **Do**: 날씨를 정하고, 도구를 사용하고, 읽고, 쓰고, 같은 목록으로 돌아간다.
- **Feel**: 고요·위안·외로움·호기심·긴장 등 복합 감정을 품는다. 화면의 과도한 강조는 이 분위기를 방해할 수 있다.
- **Pain**: 결과와 글쓰기 분리, 판정의 맥락 상실, 선택 확장의 과도한 첫 화면 노출, 기록 저장 여부 불확실성.
- **Gain**: 필요한 한 규칙이 바로 보이고, 글이 남아 있고, 다음 임무를 빠르게 시작할 수 있는 확신.

## 🎨 DEFINE: Frame the Problem

### Point of View Statement

**밤에 혼자 이야기와 감정을 기록하는 등대지기는 판정·관련 규칙·글쓰기·다음 선택을 한 작업 맥락에서 이어가야 한다. 매 임무를 저널에 해석한 뒤 목록으로 돌아가는 반복이 게임의 핵심이기 때문이다.**

### How Might We Questions

1. 필요한 판정의 의미를 사용자가 따로 찾지 않고 즉시 읽게 할 수 있을까?
2. 시작의 단발 절차와 밤의 반복 절차를 명료하게 구분할 수 있을까?
3. 하나의 결과를 자신의 글로 옮기는 동안 카드/주사위 값을 잃지 않게 할 수 있을까?
4. 어떤 임무든 선택하면서 선택 확장은 쉽게 꺼내 쓸 수 있게 할 수 있을까?
5. 실물 도구와 디지털 도구 모두 같은 기록 흐름을 사용할 수 있을까?
6. 시간 왜곡이 밤의 흐름을 바꾸면서 기존 글을 보존하게 할 수 있을까?
7. 작은 모바일 화면에서 필요한 정보만 보이게 하면서 데스크톱의 여유를 활용할 수 있을까?

### Key Insights

- 중요한 정보구조 단위는 룰북의 챕터나 기능 모음이 아니라 **현재 밤, 기록들, 참고**다.
- 선택권과 절차의 정확성을 함께 유지해야 한다. 선형 진행만 제공하면 밤의 자유 반복·미니게임을 어렵게 만든다.
- 기능이 존재한다는 것과 실제 루프에서 손쉽게 쓸 수 있다는 것은 다르다.
- 자동화가 서술 해석을 대신하면 원문의 개방성을 해친다. 물건 상태, 문양 결과, 계절의 서술 영향은 쓰는 사람에게 남겨둔다.
- 실사용자 검증은 별도 필요하다. 이번 결정은 룰북 충실성과 대리 과제 수행을 우선하는 설계 판단이다.

## 💡 IDEATE: Generate Solutions

### Selected Methods

SCAMPER Design과 Journey Mapping을 결합한다. Analogous Inspiration으로 책상 위 카드·주사위·로그북의 물리적 배치를 참고하고, Assumption Testing으로 기존 메뉴/레이아웃이 제약이라는 가정을 제거한다. 충분히 발산한 후에만 평가한다.

### Generated Ideas

1. **Substitute**: 기능 카탈로그 홈을 “오늘 밤 시작/이어가기” 작업 시작점으로 교체.
2. **Combine**: 임무 선택·판정 도구·결과 해석·기록을 하나의 임무 카드에 결합.
3. **Adapt**: 책상 위의 로그북처럼 넓은 화면은 기록 중심, 관련 규칙은 옆에 배치.
4. **Modify**: 현재 세션 단계와 날짜·날씨·불빛을 작은 상태줄로 표현.
5. **Eliminate**: 시작 전 필수 플레이북/계절 선택을 제거하고 선택 확장으로 이동.
6. **Reverse**: 규칙 전체를 먼저 읽기보다 행동 중 필요한 규칙만 펼침.
7. **Combine**: 카드 값/문양/색의 서로 다른 의미를 결과 옆에 바로 연결.
8. **Adapt**: 실물 카드/주사위/동전 결과를 직접 입력하여 동일한 해석 흐름 사용.
9. **Modify**: 대기 임무 하나와 작성 중 글을 자동 저장하여 새로고침 후 재개.
10. **Eliminate**: 같은 기능의 중복 메뉴·장식성 통계·상시 유틸리티를 줄임.
11. **Purposes**: 날씨 양식을 감정 선택뿐 아니라 기온·시야·소리를 담는 기록 출발점으로 활용.
12. **Journey**: 점등 성공 뒤 “태엽 감기”를 작은 명시 단계로 둠.
13. **Journey**: 사건9/K에 “마무리로 이동/밤 다시 시작”을 노출하고 과거 기록 보존.
14. **Journey**: 수집은 카드 한 장→동전→물건 서술/보관→다음 카드로 순차 진행.
15. **Combine**: 빛에게 묻기는 질문·두 동전·응답 해석·지난 대화와 밤당1회 상태를 연결.
16. **Modify**: 계절은 누적 징후·다음 날 시작·활성 기간을 구별하고 선택 시작/1d6 시작도 지원.
17. **Eliminate**: 모바일에서는 비어 있는 참고 패널을 숨기고 맥락 드로어로 보조 도구 제공.
18. **Analogous**: 마무리를 로그북을 닫는 행위로 설계해 소등·셔플·최종 소감을 묶음.

### Top Concepts

| 개념 | 장점 | 비용/마찰 |
|---|---|---|
| **규칙 조회 대시보드**: 모든 표와 도구를 한눈에 제공 | 숙련자가 표를 빨리 찾음, 구현 간단 | 글쓰기와 현재 절차가 약함, 모바일 긴 스크롤, 선택 확장과 핵심의 위계 혼란 |
| **안내형 선형 위저드**: 시작부터 끝까지 한 단계씩 | 처음 플레이의 순서 명확 | 임무 반복·자유 선택·미니게임·재점등·K 재시작에 경직, 되돌아가는 조작 증가 |
| **세션 책상**: 오늘 밤 중심의 판정·기록 + 맥락 도구 | 반복/쓰기의 연결, 원문 자유, 모바일 축약, 선택 확장 접근 | 상태/자동 저장/덱 일관성 설계가 필요 |

선택: **세션 책상**. 판단 순서는 룰북 충실성·기록 루프 속도 → 모바일 조작/인지 부담 → 시각 일관성이다. 미관만으로 선택하지 않았다. 상세 가중 평가와 구현 계획은 동반 Problem Solving 문서에 기록한다.

## 🛠️ PROTOTYPE: Make Ideas Tangible

### Prototype Approach

Storyboarding과 Role Playing으로 정상 흐름 및 예외를 검토한 후 코드에서 실제 상호작용을 구현한다. 정적 시안에서만 끝내면 저장·덱·특수 사건의 연결을 확인할 수 없으므로 작동하는 제품을 검증 대상에 둔다.

### Prototype Description

- 주 내비게이션 **오늘 밤 / 로그북 / 참고**.
- 오늘 밤은 시작→점등→태엽→자유 임무 반복→마무리의 현재 맥락을 유지.
- 판정이 끝난 대기 임무 하나를 자동 저장하고 글을 기록한 뒤 다음 임무로 이동.
- 등대지기·계절·미니게임·보관함은 맥락 드로어에서 접근.
- 실제 덱 상태를 저장하며 실물 결과 입력도 지원. 판정값과 해석을 함께 표시.
- 날씨의 자유 메모, 별도 태엽 감기, 특수 사건에서 기록 보존.
- 계절 징후는 하루에 한 번, 충족 다음 날 시작. 기간은 원문대로 유지.
- 어둠의 빛은 응답 어휘군과 밤당 한 번 제약, 수집은 순차 카드/동전과 수정 가능한 보관물.

원문 불명확성: Striking은 1d6÷2에 반올림 없음 → 0.5일 단위를 표시. 수집 동전은 앞면=정상이라는 대응이 없음 → 상태를 플레이어가 적음. 날씨→계절 연결은 서술 조건 기반이며 강제 단일 자동 분류를 발명하지 않는다.

### Key Features to Test

1. 시작 날짜/시간·날씨 메모와 점등 실패 반복, 성공 후 태엽.
2. 관찰/정비의 d6→카드 해석과 기록→다음 임무.
3. 사건 색/값,4 재점등 참조,9 마무리,K 기록 보존 후 재시작.
4. 새로고침 후 세션·대기 임무·글·덱 복원.
5. 수집 수량/순차 진행·물건 보관·세션 간 재사용.
6. 빛의 질문과 두 동전·한밤 한응답·지난 대화.
7. 계절 세 시작 방법과 기간·종료 후 징후 초기화.
8. 모바일·데스크톱 가독성, 핵심 버튼 접근, 키보드/포커스, 드로어, 스크롤.

## ✅ TEST: Validate with Users

### Testing Plan

이번 작업의 검증은 **룰북 대조, 자동 기능 검사, 브라우저의 과제 기반 대리 사용성 수행**이다. 참가자를 모집하지 않았으므로 실사용자 테스트가 아니다. 가능한 미래 테스트는 초보/경험자5–7명에게 짧은 밤을 실제로 플레이하게 하고 생각을 소리내 말하게 하는 방식이다.

대리 과제: 첫 밤 시작, 여러 임무 후 기록, 사건9/K, 수집2개, 빛 질문, 계절 누적/기간, 모바일에서 재개 및 마무리. 측정은 행동 수, 필요한 규칙까지의 메뉴 전환, 기록 유실/규칙 오류, 가로 스크롤·잘림, 포커스 이동. 디자인 의도와 실제 검증 결과를 구별한다.

### User Feedback

**실제 참가자 피드백: 수집하지 않음.** 실제 사용자 발언·만족도·속도 개선 수치를 만들어내지 않는다.

**실제 실행 결과: 완료.** 규칙·저장 검사24/24,브라우저 시나리오10/10,ESLint,production build가 통과했다. 320·390·768·1440px 및 종이/밤 테마,관련 규칙1클릭,임무 반복의 메뉴 전환0,Escape 포커스 복귀를 확인했다. 최종 독립 재검토에서 드러난 실제 셔플 횟수·수색 예약 묶음·따뜻함3밤 단위도 수정하고 검사했다. 구체적인 명령·근거·한계는 [최종 검증 기록](verification-2026-10-08.md)에 있다.

### Key Learnings

독립 룰북 분석에서 확인한 배움: 한 번의 시작·무제한 임무 반복·자율 마무리를 구분해야 하며, 옵션 기능보다 매 결과를 자신의 기록으로 만드는 연결이 중요하다. 구현 후 과제 수행에서 백업 형식 불일치, K 종료 우회, 모바일 도구 접근 및 포커스 문제를 발견해 고쳤다. 결과부터 읽는 순서와 작성 중 데이터의 연속성이 시각적 단장보다 우선한다는 판단을 확인했다.
