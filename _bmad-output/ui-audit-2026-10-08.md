# 최종 독립 UI 스모크 감사

검증일: 2026-10-08 (Asia/Seoul). 대상: 최신 production preview `http://127.0.0.1:5299`.

## 방법과 범위

별도 Playwright Chromium headless 브라우저와 각 폭별 신규 컨텍스트를 사용했다. 화면 폭은 320, 390, 768, 1440px, 화면 높이는 900px다. 실제로 수정된 앱을 열고, 관리자 플레이북의 정비 3번·클럽 카드와 작성 중인 일지를 로컬 초기 상태로 제공했다. DOM 결과, 화면 캡처, 클릭·Tab·Escape 동작과 브라우저 pageerror를 관찰했다. source는 수정하지 않았다.

전체 플레이 규칙 시나리오, 실제 사용자 세션, 실물 모바일 키보드 사용을 이 감사의 결과로 주장하지 않는다.

## 직접 확인한 결과

| 항목 | 관찰 결과 |
|---|---|
| 가로 레이아웃 | 320·390·768·1440px 모두 document scrollWidth가 viewport 폭과 같았다. 가로 넘침이 없었다. |
| 모바일 내비게이션 | 320·390px에서 오늘 밤·일지·규칙 찾기·도구의 네 버튼이 모두 보였다. 도구 버튼 클릭으로 도구 패널이 열렸다. |
| 데스크톱/중간 폭 | 768·1440px에서는 도구 탭이 숨겨지고 우측 도구 목록으로 접근했다. 해변 수색 버튼으로 패널이 열렸다. |
| 모바일 중복 도구 | 최신 빌드의 모바일 화면에서는 본문 아래 동일한 도구 목록이 숨겨졌다. 하단 도구 탭을 통해 접근했다. |
| 결과 읽기 | 네 폭 모두 정비 결과 제목 H2에 포커스가 있었고 초기 scrollY는 0이었다. 쓰기칸 자동 포커스 때문에 제목이 화면 밖으로 이동하던 현상이 재현되지 않았다. |
| 정비 안내 중복 | 판정 뒤에 작업 질문이 한 번 표시되었다. 앞에 같은 내용의 정비 description 문단이 반복되지 않았다. |
| 도구 패널 폭 | 모바일 패널의 scrollWidth/clientWidth는 319/319, 389/389였다. 768·1440px의 패널은 589/589였다. 패널 내부 가로 넘침은 없었다. |
| Escape | 320·390px에서는 패널을 닫은 뒤 원래 도구 버튼에 포커스가 돌아왔다. 768·1440px에서는 원래 해변 수색 버튼에 돌아왔다. |
| Tab | 모바일 도구 패널에서 여섯 차례 Tab 이동 중 포커스가 패널 내부 컨트롤에 머무는 것을 확인했다. |
| 밤 화면 | 각 폭에서 보관 및 설정을 열고 밤 화면 버튼을 누른 후 dataset.theme이 night가 되었고 화면 색이 전환되었다. 캡처에서 본문, 입력칸, 카드 판정과 주요 버튼을 읽을 수 있었다. |
| 런타임 | 각 폭의 진입·패널 열기·닫기·밤 화면 전환 중 pageerror는 0건이었다. |

## 결론

이번에 직접 확인한 화면과 조작에서 진행을 막는 오류나 추가 수정이 필요한 레이아웃 문제를 발견하지 않았다. 앞서 발견한 모바일 도구 접근, 패널 종료 후 포커스 복귀, 정비 안내 중복, 쓰기칸 자동 스크롤의 네 문제가 최종 빌드에서 해결된 것을 확인했다.
